# 资源加速器图片尺寸影响调查报告

## 调查概述

**调查日期**：2026/05/14  
**调查对象**：Chrome 扩展资源加速器（Resource Accelerator）  
**调查目标**：确认资源加速器是否会改变页面图片的显示尺寸或实际尺寸

---

## 1. 总体结论

**资源加速器会有条件地改变图片的实际压缩尺寸，但不会改变其在页面上的显示尺寸。**

具体来说：
- ✅ **DOM/CSS 层面**：不会修改页面图片的显示尺寸
- ⚠️ **压缩层面**：大尺寸图片会被有条件地缩小（最大 2048 像素限制）
- ✅ **布局层面**：不会造成页面布局偏移（CLS）

---

## 2. 详细分析

### 2.1 压缩环节的尺寸影响

#### 2.1.1 默认尺寸限制
- **默认最大尺寸**：2048 像素（宽或高）
- **缩放规则**：当图片原始尺寸超过 2048 像素时，会按比例等比缩放，保持原始宽高比不变
- **小尺寸图片**：如图片原始尺寸小于所有限制条件，压缩后尺寸与原图完全一致

#### 2.1.2 自适应压缩策略
- **设备等级适配**：根据设备性能等级调整 `maxWidth` 参数
- **网络质量适配**：根据网络质量动态调整尺寸限制
- **大图片额外处理**：超过 `largeImageThreshold` 的图片会额外应用 0.7 的缩小系数

#### 2.1.3 压缩流程
```
原始图片 → 检查尺寸限制 → 超过限制则等比例缩放 → 质量压缩 → 输出
           ↓（未超限）
         直接压缩
```

### 2.2 DOM/CSS 环节的尺寸影响

#### 2.2.1 DOM 属性处理
- ❌ **不修改**：不会直接修改 `<img>` 标签的 `width`/`height` HTML 属性
- ❌ **不修改**：不会修改图片的 `src` 属性指向的图片显示尺寸
- ✅ **仅优化**：通过 `srcset`/`sizes` 提供多分辨率选项，由浏览器选择

#### 2.2.2 CSS 注入策略
所有注入的 CSS 规则均为**保护性**，目的是防止布局偏移（CLS）：

| CSS 属性 | 作用 | 是否改变显示 |
|---------|------|-------------|
| `min-height` | 为图片预留最小空间 | ❌ 不改变 |
| `aspect-ratio` | 保持图片原始宽高比 | ❌ 不改变 |
| `background-color` | 懒加载占位背景色 | ❌ 不改变 |

**关键限制**：尺寸预留仅对没有设置 `width`/`height` 属性的图片生效，已有尺寸属性的图片不受影响。

#### 2.2.3 懒加载实现
- 不使用占位图（placeholder）
- 仅设置背景色作为视觉占位
- 图片加载完成后无缝显示，无尺寸跳变

### 2.3 设计与实现的差异

#### 2.3.1 设计文档内容
设计文档中明确的图片优化范围：
- ✅ 质量压缩
- ✅ 格式转换（WebP/AVIF）
- ✅ 懒加载策略
- ✅ 预加载策略

**缺失项**：所有设计文档中**均未提及**尺寸限制或缩放功能。

#### 2.3.2 差异分析
| 项 | 设计文档 | 实际实现 | 差异 |
|----|---------|---------|------|
| 尺寸限制 | 未提及 | 2048 像素上限 | ❗ 存在差异 |
| 自适应缩放 | 未提及 | 设备/网络适配 | ❗ 存在差异 |
| 显示尺寸修改 | 未提及（隐含不修改） | 不修改 | ✅ 一致 |
| 布局影响 | 防止 CLS | 防止 CLS | ✅ 一致 |

## 3. 用户影响分析

### 3.1 什么情况下用户会察觉到图片尺寸变化

#### 可能察觉的场景
1. **查看大图场景**：用户右键"在新标签页中打开图片"时，会发现图片实际尺寸被缩小
2. **保存图片场景**：用户保存图片到本地时，文件尺寸小于预期
3. **高精度需求场景**：设计师、摄影师等需要查看原始分辨率图片的用户

#### 不会察觉的场景
1. **正常浏览**：页面显示尺寸不受影响，视觉上无差异
2. **响应式图片**：网站本身使用 `srcset` 提供多尺寸时，效果一致
3. **小图片**：尺寸在 2048 像素以内的图片完全不受影响

### 3.2 对图片质量的影响

| 影响类型 | 程度 | 说明 |
|---------|------|------|
| 像素细节损失 | 中 | 大尺寸图片缩小后会丢失部分像素细节 |
| 压缩质量 | 低 | 质量压缩参数独立，尺寸缩放不直接影响压缩质量 |
| 打印质量 | 高 | 如用户需要打印图片，尺寸缩小后打印质量下降 |

### 3.3 对布局的影响

✅ **无负面影响**
- 显示尺寸与原设计一致
- 宽高比保持不变
- 通过 CSS 预留空间反而减少了布局偏移

## 4. 建议

### 4.1 文档优化建议

**建议**：在文档中明确说明尺寸限制

**理由**：
1. 当前实现与设计文档存在差异，需要补充说明
2. 避免用户（尤其是开发者）在不知情的情况下遇到问题
3. 体现功能透明度，增加用户信任

**具体行动**：
- 在 README 或功能说明中添加"图片尺寸限制"章节
- 说明默认 2048 像素限制的原因（性能、内存考虑）
- 说明自适应缩放策略

### 4.2 功能增强建议

**建议**：添加用户可配置的尺寸选项

**配置项建议**：
```javascript
{
  imageCompression: {
    maxWidth: 2048,           // 允许用户修改或禁用
    maxHeight: 2048,          // 允许用户修改或禁用
    enableAdaptiveResize: true,  // 自适应开关
    largeImageScale: 0.7,     // 大图片缩放系数
    preserveOriginal: false   // 保留原始尺寸选项
  }
}
```

**优先级**：中高
- 对于普通用户：默认值合理，无需修改
- 对于专业用户：提供配置选项满足特殊需求

### 4.3 用户通知建议

**建议**：可选的轻量级通知机制

**方案 A（保守）**：
- 仅在扩展设置页面说明尺寸限制
- 不主动打扰用户

**方案 B（平衡）**：
- 首次使用时显示一次性提示
- 提示内容："为优化性能，大尺寸图片将自动缩放至 2048 像素以内，可在设置中调整"
- 提供"不再提示"选项

**推荐**：方案 A，待用户反馈后再考虑更主动的通知

### 4.4 技术优化建议

1. **缩放质量优化**：使用更优的缩放算法（如 Lanczos）减少细节损失
2. **智能检测**：检测网站是否为摄影/设计类站点，自动放宽限制
3. **原始尺寸缓存**：对于频繁访问的大图片，可选项缓存原始版本
